\section{Introduction}
\label{sec:introduction}

An engineer bringing up a sensor reads its register settings, timing and supply limits from a datasheet of 59 to 162 pages. The six Bosch Sensortec datasheets used here, for the BME280~\cite{bme280}, BMP390~\cite{bmp390}, BMI270~\cite{bmi270}, BMM350~\cite{bmm350}, BMA456~\cite{bma456} and BHI360~\cite{bhi360}, run to 597 pages between them. Asking a language model is faster than searching them, but the answer comes from what the model remembers. On the held-out questions of \cref{sec:evaluation}, a model answering from memory gave a wrong answer to 4.3 of 50 questions per run, among them a reset value and a gyroscope sensitivity, and nothing in those answers told the reader which ones to distrust.

The usual remedy is retrieval: search the documents and give the model the passages it needs, so that it answers from text rather than memory~\cite{lewis2020}. Retrieval removes most wrong values, as \cref{sec:results} shows, but the reader still takes the model's word that the passage says what the answer says. The model may cite a page and quote a passage that the page does not contain, or quote the right passage and state a number that is not in it. Checking either by hand means opening the datasheet, which is the work the assistant was meant to save.

The assistant described here closes that gap in code. Each answer must cite the page and quote the passage it came from. Before the answer is shown, code confirms that the quote appears word for word on the cited page and that every number in the answer appears in a quote. An answer that fails is sent back to the model once with the reason; if the revision also fails, the user is told there is no verified answer. The guarantee is deliberately narrow. Every number shown appears in a passage quoted verbatim from the page cited, so a reader can confirm it in seconds. It does not promise that the number answers the question.

The question this report answers is what the check costs and what it buys. \Cref{sec:system} describes the system and \cref{sec:evaluation} the evaluation: four arms, from the model alone to search with the check and one revision, scored by code on a development set and a held-out set. \Cref{sec:results} gives the results, \cref{sec:discussion} interprets them and sets out what the check cannot catch, and \cref{sec:reproduction} lists the commands and commits behind each run.
